# issue 22

## comment 2026-11-14 1

今の Hakyll は `flag` セクション（[リンク](https://cabal.readthedocs.io/en/3.18/cabal-package-description-file.html#configuration-flags)）を使っている。

しかしながら、あらゆる `True` と `False` の組み合わせについて、それらすべてにおいてビルドできることを保証することは難しい。それぞれのパターンにおいて CI するにしても組み合わせ爆発が起きてしまう。

結果として、どれかの組み合わせにおいてビルドできなくなるという事態が発生しやすくなってしまうため、フラグを多用することは避けるべきである。

最初はフラグを消すと同時にコードの内部の `CPP` 言語拡張によるプリプロセッサを消そうと思っていたけど、いきなりコードの内部にまで触るのは大変である。

かといって、 `build-depends` フィールドにおいて重複が発生していたりと `cabal` ファイルの内容が複雑になっていたり、 `stack.yaml` ファイルの内容においてフラグを指定しているため、うっかり指定を忘れると Stack を使わないでビルドする時と一致しなくなる危険性があって、ファイルの内容が美しくなくなっていたり、と様々な問題が発生している。

そのため、まずはすべてのフラグについて `True` をデフォルトにして、その状態を前提にして `build-depends` フィールドを統合したり `stack.yaml` ファイルを変更したりする。
